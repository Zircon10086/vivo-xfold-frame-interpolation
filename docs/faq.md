# FAQ

**Q：开机会多一次重启，正常吗？**
A：正常。模块要重启 `vivo-configstore-hal` 和 zygote 才能让属性生效，代价是约 30 秒的额外启动时间。这是刻意的设计：在 `post-fs-data` 阶段挂 `/vendor` 会让 init SIGABRT、卡开机 logo（已实测）。

**Q：模块装上后，游戏侧栏没有「游戏插帧」？**
A：按顺序排查：
1. WebUI 状态是否为「能力已就绪 / 已声明」；不是就点「重新应用能力」。
2. 该应用是否已导入（游戏侧栏只在配置表里有该包名时出现入口）。
3. 游戏魔盒是否在后台被省电策略杀掉。
4. 应用本身是否允许悬浮窗（系统应用常见问题）。

**Q：三个档位只出现两个？**
A：「优化功耗」这一档需要 `optimize_power_v3_60_30_60` 行存在。本模块导入时会写齐，如果是旧版本导入的应用，重新导入一次或点「刷新」。

**Q：为什么只有 60→120 和 30→60？**
A：系统 `computeUsecaseForGame` 只认这两组能落到 120Hz/60Hz 的显示用例；45→90 需要原生 45 帧（本机走 -100 分支到不了），48/72→144 在 120Hz 面板上没有意义。

**Q：能同时开 60→120 和 30→60 吗？**
A：配置层可以同时存在，但同一时刻只有一个档生效。`support_sdk=0` 时系统把 -100 传下去、三段判断全跑，30 段最后覆盖，结果必然是 30→60；`support_sdk≠0` 时按实测原生帧率选档。结论是「不能同时生效」，所以本模块只写入两档所需行，由你在面板里选。

**Q：超分（super_resolution）为什么没有？**
A：本机型/游戏没有出现入口，模块默认不写这一行。需要实验可手工 `vivo-memc.sh set-flag <pkg> sr on`。

**Q：「恢复游戏魔盒初始设置」做了什么？**
A：`pm clear com.vivo.gamecube`，清空游戏魔盒的全部应用数据：导入的插帧配置、魔盒自己的「支持游戏」名单、悬浮窗设置都会回到出厂状态，之后需要重新导入。操作前有二次确认。

**Q：导入的应用数据存在哪里？**
A：游戏魔盒的 SQLite：`/data/data/com.vivo.gamecube/databases/support_dimension_list.db`，表 `game_dimen`。每次清理前会备份到 `/data/local/tmp/vivo-memc-backup/`。

**Q：卸载后游戏魔盒里还留着这些应用吗？**
A：留着。要清掉用「恢复游戏魔盒初始设置」，或卸载模块后重装游戏魔盒。
